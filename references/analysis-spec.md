# 单 Agent 产出物与重构规范

## 1. 行为记录和逻辑图

沿真实任务记录“触发 → 接收输入 → 澄清/读取资料 → 规划或判断 → 调用能力 → 接收结果 → 检查/修改 → 交付或等待”。顺序由产品决定，不要求每个 Agent 都有所有节点。将实际操作与材料复盘分开，保存原始输入、结果及关键截图。

逻辑图画具体产物和条件，不只画“分析、执行、完成”。确认点写用户确认什么，失败分支写重新执行、局部修改、退出或转人工。未测分支标公开规则或推断；没有发现失败不虚构异常。时间、成功率与效果只在真实测量后报告。

## 2. 工作机制说明

先写 Agent 的目标、边界、输入输出和谁触发它；再解释哪些步骤固定、哪些由模型选择，工具结果是否影响下一步，以及如何判断结束。可能是动态行动循环、先计划再执行、固定流程内局部 Agent，或其他方式。

区分三个问题：Agent 的内部工作方式、外部流程如何控制它、它与其他 Agent 的关系。不要用 UI 的职业角色证明内部结构，或把调用一次模型称作完整 Agent。缺少内部记录时给最小可解释候选方案与替代解释，不写唯一架构。

## 3. 上下文、状态与产物约定

用短字段表说明：信息项/产物、来源、必需性、读取者、写入者、更新条件、存储/生命周期（已知时）、证据性质。可覆盖用户输入、会话历史、资料检索、任务计划、工具结果、确认记录和最终产物，不硬造共享全局上下文。

必要状态图表达等待输入、执行、等待确认、完成、失败等实际状态；重构的状态名明确标假设。解释如何局部修改、重新确认、恢复稳定节点，是否影响已交付产物。概念字段不是竞品数据库 Schema；提出 Schema 时说明它属于原型设计。

## 4. Tool 清单和定义

清单字段：工具名称、用途、触发条件、输入、输出、权限/副作用、失败恢复、证据性质。公开名称原样保留；未知名称使用研究者命名，并明确不是实际 API。Tool 可包含读取/检索、计算/生成、状态管理、UI 确认、外部执行及下游调度，但只有对应行为或材料支持时才推导。

关键工具定义草案应具体到：

- 名称和职责边界；何时允许/禁止调用。
- 参数类型、必填项、约束，以及参数来源。
- 返回结构、成功/失败区分及下步处理。
- 涉及外部修改时的权限、确认与重复调用风险；必要时讨论幂等、超时、重试或回滚，不假设实际存在。
- 一组输入/返回样例，与提示词中的工具名和字段一致。

不把普通文字提示自动当成表单工具，不把每个功能硬拆为独立 Tool。不输出空泛的“搜索工具、生成工具”代替可解释的调用约定。

## 5. 完整提示词反推稿（七部分）

标题明确“研究者重构的提示词草案，非竞品原始配置”。结合实际行为写成可供原型测试的完整文本，不把七个标题留空，不照搬参考文章的 JSON-only 或固定工具规则。

1. **角色与目标**：任务、成功标准、职责和非职责。
2. **输入约定**：触发来源、所需字段/材料、上下文读取范围、缺失或冲突信息的处理。
3. **输出约定**：交付产物、状态写入、消费者及完成标志。
4. **硬约束**：权限与读写边界、数据一致性、必须确认的事项、禁止行为；有证据的规则与原型新增建议分开。
5. **执行流程**：具体步骤、条件分支、动态工具选择、修改、失败、重试、等待和停止条件。
6. **工具调用规范**：工具名称、参数来源、调用时机、返回结果处理；不引用 Tool 清单中不存在的工具。
7. **响应格式与样例**：依任务选自然文本/结构化对象/资源产物。若用 JSON，样例有效，字段对应输入输出约定；等待确认与完成至少说明各自响应，适用时给示例。

输入缺失、工具失败、用户修改等案例按场景选择用于一致性走查；没有实际运行时称“静态走查”，不是工具或效果测试。只请求可见行动记录、简短决策依据，不要求隐含思维链。

## 6. 诊断和借鉴

每个重要问题按“现象 → 用户影响 → 证据 → 原因假设 → 改善方案 → 验证”写。重复确认可能由调度、状态或工具失败等不同原因造成，不凭一张截图断言提示词缺陷。建议应说明改提示词、工具、外部状态/调度哪一部分，不能认为所有问题都靠 Prompt 修复。

借鉴点写机制、解决的问题、有效条件、迁移前提和风险。研究目的不是证明竞品原实现，而是获得可信、可测试的设计启发。

## 两种交付模式

独立报告按六步组织，开头用短结论，末尾总结借鉴点和覆盖限制。由竞品 Skill 调用时，六组产物嵌入技术层下对应 Agent 的小节；引用用户层既有截图和场景，不重复长篇背景。总体串并行、主子/对等关系和多 Agent 协作图由竞品 Skill 负责，本 Skill 描述单 Agent 如何读取上游、交付下游及处理调度。

证据索引和详细版本放末尾；关键未知及反推性质就近提醒。所有反推文档保持一致的工具名、字段、状态、调用顺序和停止条件；实际配置与建议配置不混在同一份未标注草案里。
